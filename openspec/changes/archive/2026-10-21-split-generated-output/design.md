# Design

## Context

Today one Tera template (`moon/Tiltfile.moon.tera`) renders `output`. Its blocks are header, preamble, args, project_tiltfiles, moon_resource, resources, images, workloads, selection, and footer. Custom templates (`template`) `{% extends %}` it and override blocks.
- `sync_files` writes `output` through `write_if_changed`, which already skips unchanged content.
- `generate --check` compares one file.
- `render_main_tiltfile` creates the main Tiltfile with an `include()` when it's missing.

The plugins are in alpha. The goal is one rendering path, not a split mode alongside the single file.

Verified against Tilt 0.37.8 in a spike:
- A generated entry `Tiltfile` that `include()`s section files, which `load()` shared definitions from a `.star` module, loads correctly.
- `load()` can't import names starting with `_` (`names with leading underscores are not exported`), but aliasing works: `load("./lib.star", _moon_path = "moon_path")`.
- `config.define_*` can't be called after `config.parse()`, anywhere, and included files don't share variables. A `.star` module that defines and parses the args, loaded by several files, runs once and works.
- `config.set_enabled_resources()` works from an included file.
- `watch_settings()` from an included file applies to every resource.

## Goals / Non-Goals

**Goals:**
- One output layout: small, per-concern files, where a config change touches only the affected ones.
- A gitignored setup that works from a fresh clone.
- Per-file customization, without a second rendering path.

**Non-Goals:**
- Keeping single-file output, or `template`'s whole-file override.
- Rewriting users' main Tiltfiles. They're user-owned, so migration is a message.

## Decisions

**Files in `outputDir` (default `.moon/tilt`):**

| File | Section | Contents |
| --- | --- | --- |
| `Tiltfile` | `Tiltfile` | Entry: `watch_settings`, project Tiltfile includes, then `include()`s `resources.tilt`, `images/*.tilt`, `workloads.tilt`, `selection.tilt`, in that order |
| `lib.star` | `lib` | `MOON_ROOT` (from its own location), `moon_path`, `MOON_ENV`, `MOON_GITIGNORE` |
| `args.star` | `args` | Tiltfile args (`config.define_*`, `MOON_CFG = config.parse()`) and `moon_edit`. With `selectByProject: false`, `MOON_CFG = {}`. |
| `resources.tilt` | `resources` | The `(moon)` resource and local resources |
| `images/<project>.tilt` | `image` | One per image (the context adds `image`). Loads `restart_process` itself when it needs it. |
| `workloads.tilt` | `workloads` | Workload decorations |
| `selection.tilt` | `selection` | `_MOON_PROJECTS` and `set_enabled_resources` |
| `.gitignore` | (none) | `*` |

Section files that would be empty (no images, no workloads) aren't written.

**Sections use today's names through aliased loads.** Each section file starts with a header and the `load()` lines it needs, such as `load("./lib.star", _moon_path = "moon_path", _MOON_ROOT = "MOON_ROOT", ...)` and `load("./args.star", _moon_cfg = "MOON_CFG", _moon_edit = "moon_edit")`. Section bodies keep using `_moon_path`, `_MOON_ENV`, and so on, and the `moon_path` filter and macros are unchanged. Every section gets the same template context (as today), and the image section also gets `image`.

**Section templates are the only templates.** The built-in template becomes `moon/sections/<section>.tera`, one per row above, with blocks inside each so overrides can stay small. `templateDir/<section>.tera` replaces a section and can `{% extends "moon/sections/<section>.tera" %}`. A `.tera` file there that names no section is an error, so a typo can't silently do nothing. `--template-dir` replaces `--template`. The whole-file template and its `footer` block go away: workspace-wide additions belong in the main Tiltfile.

**Ownership by header.** Every generated file starts with the `Code generated by tilt_extension` header (`.gitignore` with a `#` comment version). Pruning deletes only files under `outputDir` that carry it and weren't produced, so a user's file in the directory survives.

**Bootstrap main Tiltfile.** A missing main Tiltfile is created as:

```python
local([<moonBin>, "ext", <extension id>, "--", "generate"], quiet = True)
include("./.moon/tilt/Tiltfile")
```

This doesn't loop, because generation doesn't rewrite unchanged files, so Tilt sees no change to the files it watches. That guarantee gets its own integration test (mtime and inode). Workspaces that commit the output can drop the `local()` line.

**Migration.**
- `output` and `template` remain only as config fields that fail generation with a message pointing to `outputDir` or `templateDir`. During sync, that error is recorded, as usual, without blocking `moon run`.
- A `Tiltfile.moon` at the workspace root with the generated header is deleted once, with a message showing the bootstrap line. Leaving it would let an old main Tiltfile silently include stale output; deleting it makes Tilt fail loudly on the old `include()`.

**Sync reports only files to commit.** moon trusts the files a sync reports, not git status. Checked with moon 2.6.2 in CI mode: it warns "Files were modified during workspace sync that should be committed" for every reported `.moon/tilt` file, even though the directory ignores itself. So sync reports only the main Tiltfile and a deleted `Tiltfile.moon`, and a gitignored output needs no `sync: false` in CI.

**Watching.** The gitignore exceptions in `watch_settings` and the `(moon)` resource's always-watched files use `<outputDir>/**`, so the self-ignored output stays watched. `templateDir/**` replaces the custom template file.

## Risks / Trade-offs

- [Every workspace must update its main Tiltfile] → An explicit error or message with the exact line, a README migration section, and a `feat(tilt)!` release.
- [Bootstrap costs a `moon` run per Tiltfile load] → About 2 seconds in a 30-project workspace, per the issue. It's only in the created bootstrap file.
- [Template users must move overrides into sections] → The block names inside each section match today's blocks, so most overrides move as-is into the matching section file.

## Migration Plan

Release as `feat(tilt)!` (0.x minor bump). For users:
1. Delete `output`/`template` from the extension config, or replace them with `outputDir`/`templateDir`.
2. Change the main Tiltfile's `include("./Tiltfile.moon")` to the bootstrap lines, or delete the main Tiltfile so it's created.
3. Move custom template overrides into `templateDir/<section>.tera`.
